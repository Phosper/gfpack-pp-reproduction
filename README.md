# GFPack++ NLP 课程作业

基于 [TimHsue/GFPack-pp](https://github.com/TimHsue/GFPack-pp) 的官方权重推理复现。这里保存课程作业的准备、构建和推理脚本，不包含官方源码副本、权重、数据和运行环境。论文见 [arXiv:2406.07579](https://arxiv.org/abs/2406.07579)。

## 获取源码与资源

```bash
git clone https://github.com/TimHsue/GFPack-pp.git upstream
git -C upstream checkout ff75815e24ec50cd7fa8b2abdec1acfe0b55be95
python3 prepare_assets.py
```

资源从官方提供的下载地址获取，准备脚本校验文件并生成本地来源清单。请先查看官方仓库的使用条款；本仓库不重新分发官方权重或数据。

## Linux GPU 环境与运行

需要可用的 NVIDIA GPU、CUDA 版 PyTorch、Python 和支持 OpenMP 的 C++ 编译器。已运行的环境为 Python 3.11、PyTorch 2.6.0+cu124、PyG 2.6.1，与作者环境不同。

`BASE_PYTHON` 应指向已安装 CUDA 版 PyTorch 及官方环境所需依赖的 Python。脚本创建继承该环境依赖的独立 venv，额外安装脚本列出的依赖；它不是从空环境一键安装全部依赖。

```bash
BASE_PYTHON=/path/to/python bash prepare_server.sh
bash run_server.sh smoke
bash run_server.sh full
```

`smoke` 生成 1 个候选，`full` 生成 512 个候选；二者都只评估固定样本 0、128 步、seed 3407。`full` 不代表完整测试集评测。输出写入新的 `results/` 子目录。

## 完整验证集流程

```bash
.venv/bin/python -u run_benchmark.py --root . --output results/validation_128
```

结束后执行 `.venv/bin/python verify_benchmark.py results/validation_128`，验证覆盖、配置、输出哈希及汇总计算。也可以用 `bash run_pipeline.sh results/validation_128` 一次完成评测和校验；校验通过不等于排布效果全部合格。

完整入口按顺序运行样本 0–127，每例 512 个候选、128 步、seed 3407，不训练、不调参。它在运行前冻结输入和源码 SHA256，要求官方源码版本匹配且工作区无修改；每例保留候选、轨迹、图、指标、元信息和日志。输出目录必须不存在，避免覆盖历史结果。

`summary.json` 随每例完成而更新，明确区分运行失败、没有官方有效候选和严格零交叠检查失败。平均最佳利用率分别报告“仅有有效候选的样本”和“全部 128 例、失败计零”两种口径。严格几何检查只覆盖选中的最佳有效候选，不代表所有候选都通过。`status=completed` 只代表 128 例程序执行完成，不能直接当作论文指标复现成功。

第五轮已完成18项控制及两例各512候选的三配置探针，6组运行及独立校验通过。完整论文数值配置仅4/1024候选满足参考面积50和条带边界，严格0/1024；保留发布噪声尺度的论文机制配置为265/1024、严格5/1024，但利用率与部分候选交叠仍不理想。本轮不进入该重建版本的128例论文验收，未训练，按用户要求只保留本地。

官方默认模式的第二轮全量对照已完成并校验：**120/128** 例有官方有效候选，8例没有；有效样本平均最佳利用率 **76.80%**，全部128例失败计零为 **72.00%**。严格零交叠仍未通过。首轮 `eval()` 成绩单独保留，推理模式的差异与代表样本见 [实现与失败样本检查](docs/DIAGNOSIS.md)。

第三轮完成16例开发/回归候选冻结，以及原碰撞函数的独立构建和11个小几何控制。原函数 **7/11** 个控制未通过，其中高度受限的例子在2000次迭代后新增越界，该轮结论是先修正边界和终止判断。详见 [碰撞控制验证](docs/COLLISION_VALIDATION.md)。该轮没有运行16例消融、重新采样或训练。

第四轮已提供带边界检查、移动后复查和失败回滚的独立修正版，原11例和新增34项控制全部通过。16例增强候选及GT的32次安全回归通过：2个失败代表降到本轮交叠门槛，其余6个停滞回滚；8个成功代表保留参考有效性，GT不变。样本46利用率仍明显下降，严格零交叠与完整三路消融尚未通过。详见 [碰撞修复与实际回归](docs/COLLISION_REPAIR.md)。

首轮 eval 基线于2026-10-21 14:28（北京时间）结束：**128/128 例完成、0 例程序执行失败**，入口总耗时约 **47 分 33 秒**。每例 512 候选、128 步、seed 3407，不训练、不调参。完整性校验通过：457 个冻结输入未改变，57,856 个保存输出的哈希检查通过。详细记录见 [开发日志](docs/DEV_LOG.md)。

增强后有 **78/128** 例存在官方有效候选，**50/128** 例没有；有效候选共 2,163/65,536。仅在有有效候选的78例上，平均最佳利用率为 **74.96%**；全部128例、无有效候选计零时为 **45.68%**。78例选中的官方有效最佳候选均未通过1e-9面积容差的严格零交叠检查；这不等于已穷举检查所有候选。完整性校验核对文件和汇总，不是重新独立计算几何。

此前已完成单例链路验证：固定样本 0、48 个零件、512 个候选，原始官方有效 0/512，增强后 10/512，最佳利用率 75.4713%，入口耗时约 17.52 秒，PyTorch 最大已分配显存约 0.553 GiB。这些是历史单例数据，不是当前全量评测的汇总结果。该最佳结果未通过 1e-9 面积容差的严格零交叠检查。

官方权重的全量推理、结果汇总与完整性校验流程已完成。程序执行成功不代表排布效果达标；论文指标对齐、严格零交叠与训练复现仍未完成。

对照运行可使用 `bash run_pipeline.sh results/validation_upstream_mode --upstream-model-mode`。该选项仅保留官方入口的默认模型/dropout模式，仍执行无梯度推理，不更新权重。默认不传此选项时保持此前的eval模式；输出目录必须独立。
