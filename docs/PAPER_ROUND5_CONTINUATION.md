# 第五轮真实候选：继续排查记录

2026-10-29，分支`codex/paper-reproduction`。本轮主线仍是依据论文恢复推理和增强流程，不把工程排样结果当作论文复现结果。

## 本轮拿到了什么证据

在用户资料目录中找到完整的`GFPack_paper_replay_fde10c2_20261029.zip`。从中仅提取样本0、45的paper_settings原运行，每例9个所需文件，共18个。逐个核对包清单大小/SHA256，再由回放工具核对原metadata的输出哈希。原始文件未改。

这补齐了前一份检查中缺少的真实候选坐标。此前只有日志时不能回放的限制，不再适用于本轮。未提取或运行压缩包里的脚本和原生库。

两个原运行各有512候选。本轮事先固定取各自候选0、1、2、3，共8个；不依据结果换样本。每个候选最多100轮。没有执行神经网络、重新采样或训练，也没有测试全部128例。

## 本次改了哪些实现

1. **允许合法的负y压缩回到条带内。** 原参考后端对上方越界零件直接跳过压缩。现在按几何计算可能进入条带的负y搜索区间，先验证可行起点，再二分压缩。位置必须同时通过轮廓碰撞和条带检查；如果被其他零件堵住，则不提交。没有额外硬投影或未检查的位移。
2. **停止检查与选优检查一致。** paper_sat停止时采用最终检查已经使用的面积/边界容差1e-9，并保留移动量1e-3条件。不再因为1e-22的残余一直要求数学上的面积恰好等于0。最终验收容差未放宽；legacy_native仍保留原0面积停止条件。
3. **减少重复计算。** 只做几何检查时不再重建完整碰撞位移；批量处理相交包围盒和凸块配置空间。参考后处理按候选分块运行，限制缓存失效，仍是每个候选最多100轮。阶段记录增加“碰撞修正后、整体x平移前”的测量。
4. **增加明确的固定步长对照。** 默认legacy_unit步长仍为1。非单位步长必须显式选择paper_fixed_step，运行清单记录实际步长。它仍沿相同的面积加权碰撞场更新，不增加碰撞接受/回退算法。固定步长数值没有在论文中给出，不能称0.5或1就是作者原值。
5. **增加失败说明工具。** `paper_failure_diagnostics.py`从保存坐标报告交叠对、越界零件，以及固定旋转下零件是否高于条带。它不修改坐标，也不把代码检查PASS当作排样成功。

论文依据为[第4.4节碰撞场](https://arxiv.org/html/2406.07579v2#S4.SS4)和[第5.2节增强流程](https://arxiv.org/html/2406.07579v2#S5.SS2)。128步生成、末32步约束、面积权重、条带高度和100轮上限未改。具体非凸位移、后处理步长、交替顺序和数值容差仍属于公开描述未锁定的实现细节，不能宣称已证明与作者源码一致。

两种当前步长转存float32后也都是0/8。**平均交叠和最大越界有所改善，但有候选的最大交叠恶化，不能概括为全面优于第五轮基线。** 半步也没有带来严格成功，且平均交叠和最大越界不比当前单位步长好，因此没有改成默认值。

逐阶段证据：样本0候选0的单位步长回放有45轮在碰撞更新后，两两面积之和增加。最早第4轮从6141.7927增至6639.9740，高度越界从10.52086增至10.88774。该组4个候选的压缩回退计数均为0。这里定位的是碰撞更新阶段，并不是说所有后处理问题都来自压缩或float32。

这组输入不等同于上一轮4份工程转移坐标。上一轮float64的2/4通过不能推广到第五轮的8个真实候选，更不能推广到128×512主评测。

## 为什么还不能只改后处理

核对两个原运行的**全部512个原始候选**：进入后处理前，样本0、45的平均两两交叠率已经分别为1.20961%、4.32185%，严格可行均为0/512。这些统计来自原raw_metrics，不是本轮生成。

因此仍有明显生成阶段问题要排查。第六轮[权重兼容性检查](CHECKPOINT_ALIGNMENT.md)已经提示：同一公开权重对论文噪声/旋转输入配置与发布配置的去噪表现差别很大。来源为官方不等于训练配置已核实；GT记录改为1000也不等于已改变权重的训练分布。

这两例属于开发输入，不是论文128例的均值；交叠计数口径和作者阈值也未完全确认。不能据此声称作者结果不实，也不能证明权重是唯一原因。但本轮结果**不支持继续只靠调一个后处理步长来宣称复现成功**。

下一步优先检查匹配的网络、训练配置与采样输入，明确使用的权重是否支持论文设置；必要时应做配套训练。在没有匹配证据前，完整论文复现标志保持false，正式的128例成绩保持未完成。

## 验证与使用

42项代码/几何检查通过。加速阶段单独做过坐标回归：同一第五轮候选的前5轮，原参考代码与批量加速代码的坐标和几何轨迹完全一致，耗时37.68秒与15.25秒（单次CPU检查）。之后的合法负y起点修正、停止条件属于行为修正，不能把该速度对照说成所有最终坐标均保持不变。

最终实验使用冻结的脚本副本，完整记录代码、输入、输出哈希。候选分块不会增加单个候选的迭代预算；多块详细轨迹在post.json的chunks下，candidate_indices给出全局候选号。紧凑证据见[round5_continuation.json](paper_geometry_fix/round5_continuation.json)。

```bash
# 对同一源运行，只改后处理固定步长；输出目录均必须为新目录。
python -u replay_paper_geometry.py --source-run SOURCE --output UNIT_OUT \
  --candidate-limit 4 --post-step-size 1
python -u replay_paper_geometry.py --source-run SOURCE --output HALF_OUT \
  --candidate-limit 4 --post-step-size 0.5

# 直接查看保存坐标为何失败，报告各候选的交叠对和越界零件。
python paper_failure_diagnostics.py --source-run SOURCE --result-run UNIT_OUT \
  --output NEW_DIAGNOSIS.json
```

正式新生成仍用`run_paper_alignment.py --profile paper_settings --post-policy legacy_unit`。要做非单位步长探针，显式加`--post-policy paper_fixed_step --post-step-size 0.5`；这不是作者确认的设置。主线默认值没有改成半步，也没有回到工程双起点后处理。
