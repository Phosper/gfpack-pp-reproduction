# 官方公开入口与round8工程后处理的区别

比较对象：官方固定版本ff75815e24ec50cd7fa8b2abdec1acfe0b55be95的实际采样/压缩入口，与本仓库round8分支concave-compaction-round8（6e1338d）的工程后处理。这里不是把官方公开代码等同于论文的全部方法，也不是比较当前paper-reproduction新分支。

| 环节 | 官方公开代码实际执行 | round8工程后处理 |
| --- | --- | --- |
| 模型与权重 | 使用公开模型产生平移/旋转坐标 | 复用已有raw坐标，不训练或改权重 |
| 生成阶段 | 公开采样循环未调用论文所述末期碰撞场 | 工程入口处理保存候选，不改生成循环 |
| 后处理入口 | rm_spacing_all内rm_overlap调用被注释，执行x/y/x/y/x五遍间隙压缩 | 主动寻找局部碰撞，逐件搜索合法位置 |
| 凹形处理 | 压缩试探使用原生量化轮廓判交 | 凸分解保留凹槽，计算给定方向的禁止平移区间，再用完整真实轮廓验收 |
| 位移选择 | 按负x/负y压缩间隙 | 按16/64/256/1024/4096半径逐级搜索，优先短移动并惩罚跨度增长；局部贪心，不保证全局最短 |
| 紧凑化 | 上述五遍x/y压缩 | 修复后交替向左/向右做4遍水平紧凑化；每次接受终点合法、跨度不增加 |
| 存储精度 | 原生量化判交与最终浮点存储可能出现差异 | 每个新位置先转成float32，再严格检查写回坐标的交叠和高度 |
| 起点与选优 | 从模型批量候选中按公开判据选择 | 对同一候选的raw和第七轮旧修复结果分别处理，仅从严格合法终点选最小水平跨度 |

两起点来自同一预测候选，不用GT替代预测，也不是重新生成两批候选。后处理均不缩小零件，round8保持存储后的旋转分量，只改变平移。两种方案都能出现失败；严格检查是验收条件，不是任意输入都成功的数学保证。

官方公开评价使用面积50阈值，压缩中的量化判交另有条件；50是绝对面积，不是50%交叠。round8的项目严格判据为最大两两面积与高度越界均不超过1e-9，并检查最终float32坐标。该容差不能声称是论文的作者阈值。

round8固定16个开发候选严格16/16通过，平均条带利用率72.6870%。后来的128×1迁移结果75.5520%属于下一轮，每例仍只处理一个预先冻结候选；不能当作论文128例、每例512候选的完整复现成绩。

round8是改用了独立工程求解器来修复官方模型输出。论文则采用末期面积加权碰撞约束场及生成后的约束更新、负x/负y二分增强。round8的半径搜索、单件移动、左右紧凑化和双起点不是论文已描述的同一套算法。
